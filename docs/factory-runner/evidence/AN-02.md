## Phase boundary and residual risks

- The private factory owns hostile-code filesystem, descendant-process and
  network isolation, sandbox lifecycle, provider-side quotas, and all
  publication credentials. Runner policy is defence in depth.
- AN-02's `max_model_tokens` enforcement uses the documented deterministic
  UTF-8 byte estimate; the AN-02 gateway response has no provider-reported
  usage field.
- AN-03 owns complete append-only events, durable/resumable checkpoints,
  secret scanning and redaction, recovery, complete manifests, and
  release-grade add/delete/rename ChangeSet output.
- AN-04 owns immutable wheel/OCI release artifacts, compatibility
  certification, attestations, and the formal release receipt.

## Automated handoff

AN-03 does not start from a locally presumed success. After the implementation
and evidence commits are pushed, the phase worker opens or updates one draft
AN-02 PR. Required checks rerun against that exact PR head and
machine-verifiable acceptance evidence remains blocking. A trusted
orchestration context outside the attempt sandbox marks the PR ready,
revalidates the exact head, base, evidence, and checks, then submits one
SHA-bound normal CLI REST merge. The normal path has no separate approval
step, and protections are never waived.

Progression resumes only after GitHub has actually merged the protected PR and
automation verifies that the resulting AN-02 merge commit is the exact
`origin/main` HEAD. Attempt workers do not merge directly, write the default
branch, or hold merge, release, deployment, or branch-protection credentials.
