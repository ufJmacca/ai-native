## Phase boundary and residual risks

- The private factory owns hostile-code filesystem, descendant-process and
  network isolation, sandbox lifecycle, provider-side quotas, durable object
  upload, and all publication credentials. Runner policy is defence in depth.
- AN-03 checkpoints are portable safe-boundary records, not arbitrary process
  snapshots. Unsupported or contaminated state fails closed.
- A missing or invalid completion marker denotes an interrupted attempt.
- AN-04 owns immutable wheel and OCI releases, compatibility certification,
  attestations, and the formal release receipt.

## Automated handoff

After the implementation and evidence commits are pushed, the phase worker
opens or updates one ordinary open non-draft AN-03 PR. Required checks and
machine-verifiable acceptance evidence remain blocking. Trusted orchestration
outside the attempt sandbox requires the PR to remain open and non-draft,
revalidates the exact head, base, evidence, and checks, then submits one
SHA-bound normal CLI REST merge; there is no manual human-review gate and
protections are never waived.

Progression resumes only after GitHub has merged the protected PR and
automation verifies that its merge commit is the exact `origin/main` HEAD.
Attempt workers do not merge directly, write the default branch, or hold
merge, release, deployment, or branch-protection credentials.

Before publication, trusted host automation configured `main` with strict
required `test` and `lint` checks, admin enforcement, zero required approvals,
and force-push/deletion disabled. The later trusted CLI policy retained zero
reviews and exact-check validation while removing native auto-merge from the
normal path.
